WHAT YOU CAN TEST LOCALLY:
1. ✓ Core Reconciliation Logic
   - Data loading and parsing
   - Reconciliation algorithms
   - Output formatting
   - Column-type plugins (text, select, box, mean, mmr, same)
   → Use: python test_local.py
2. ✓ Full Lambda Flow (simulated S3 event, no AWS)
   - Tested indirectly via reconciliation tests
   - Uses mock data instead of S3 download
   → Use: python test_local.py
3. ✗ AWS S3/SQS Integration (requires AWS credentials)
   - Cannot test without real AWS resources or complex mocking
   - Test in AWS Lambda console or after deploying to dev environment
   → Test after: ./deploy.sh

HOW TESTING WORKS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
test_local.py simulates what happens in the real Lambda:
1. S3 Event Trigger
   ├─ In real Lambda: S3 sends event → Lambda downloads file
   └─ In test: test_local.py uses local file directly
2. Data Loading & Parsing
   ├─ Both: Load CSV and parse JSON annotations
   └─ Both: Identical code path (full fidelity)
3. Reconciliation
   ├─ Both: Group by subject_id
   ├─ Both: Apply column-type reconcilers
   └─ Both: Generate explanations
   = 100% TEST COVERAGE
4. Output Generation
   ├─ Both: Generate reconciled CSV
   ├─ Both: Generate transcript CSV
   └─ Both: Generate HTML summary
   = 100% TEST COVERAGE
5. S3/SQS Upload & Notification
   ├─ Real Lambda: Uploads to S3, sends SQS message
   └─ Test: Skipped (no AWS credentials)
   = NOT TESTED LOCALLY (test in AWS Lambda console)

These should be tested by:
  1. Running Lambda in AWS console with test event
  2. Uploading test file to S3 bucket
  3. Verifying output appears in correct S3 folders
  4. Checking SQS queue for status message

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
After local testing passes:
1. Update Lambda Runtime
   AWS Console → Lambda → BiospexReconcile → Configuration
   Confirm Python runtime is 3.12
2. Deploy code
   ./deploy.sh
   Answers:
   - Step 1: Create zip? → y
   - Step 2: Upload to AWS? → y (choose loc/dev/prod)
   - Step 3: Create version? → y (describe version)
   - Step 4: Update aliases? → y (choose loc/dev/prod)
3. Test in AWS
   - Upload test CSV to s3://bucket/zooniverse/lambda-reconciliation/
   - Lambda triggers automatically
   - Check CloudWatch Logs for output
   - Verify results in s3://bucket/zooniverse/reconciled/
4. Verify SQS Notification
   - Check SQS queue for status message
   - Laravel app should receive notification
   - Check reconciliation job runs in Laravel
